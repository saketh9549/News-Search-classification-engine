Phase 1: Data Modeling &amp; Storage Setup

Before writing scrapers or network workers, establish the storage layer and data schemas[2]:

Feed Registry Table: Stores your 15 RSS endpoints, their category/section tags, last HTTP ETag and Last-Modified headers, XML content hash digests, and polling timers[5][7].
Crawl Frontier / URL Queue Table: Manages individual article links discovered in the feeds, tracking status (pending, fetched, failed), retry counts (numtries), domain identifiers, and discovery timestamps[2][8].
Article Repository: Accommodates the permanent article data[5][6]:
  * Document ID / URL hash
  * Headline / Title
  * Publication date &amp; timestamp
  * Author / Byline
  * Kicker / Category (e.g., world, technology, business, sport)
  * Clean body text (stripped of HTML and ads)
  * Raw source domain (e.g., thehindu.com, bbc.co.uk)

Phase 2: RSS Feed Ingestion & Change Detection
Build the polling worker that continuously monitors your 15 RSS channels for new articles:
Feed Fetcher & Parser: Ingest the RSS 2.0 XML streams and parse the  blocks to extract link, title, pubdate, and guid.
Conditional HTTP Headers: Send If-Modified-Since and If-None-Match requests so feeds that have not published new content return HTTP 304 Not Modified, saving server bandwidth.
Feed-Level Deduplication: Compare XML hash codes and track seen article URLs or GUIDs to ensure only newly published links are pushed into the crawl frontier.
Adaptive Polling (Optional / advaRSS): For high-volume outlets (like Times of India or BBC World), adjust poll intervals dynamically during peak hours (e.g., 10:00–16:00) versus night hours using change-tracking metrics.

Phase 3: The Web Crawler &amp; Politeness Engine

This component reads pending URLs from the frontier and fetches the raw HTML pages[2]:

* Politeness Constraints: Enforce a mandatory minimum delay (e.g., 5–10 seconds) between successive requests to the same target domain (e.g., thehindu.com), preventing IP bans or server overload[13][14].
* Robots.txt Parser: Check each publisher's robots.txt before fetching article URLs[12][15].
* Network Downloa1der: Implement asynchronous fetching (e.g., using Python httpx, aiohttp, or Scrapy) with a distinct, honest User-Agent header[4].

Phase 4: Article Extraction & Content Cleaning Pipeline
Raw news pages contain clutter (navigation bars, subscription popups, ads, social widgets) that must be filtered out[16][17]:

* Boilerplate & Noise Removal: Use generic article extractors (such as trafilatura or readability) to isolate the primary story content[17][18].
* Field Extraction:
    * Extract the clean headline and body text[2][18].
    * Extract publication timestamps using OpenGraph tags, JSON-LD metadata, or regex date parsers[18].
    * Extract bylines/authors and section tags[6][18].
* Article Validation Filter: Discard non-article pages (e.g., category landing fronts or video galleries) by checking link-to-text density and minimum body word counts[18].
* Storage Commit: Write the cleaned, validated records into your permanent database or JSON-lines store[6][19].

Phase 5: Search Indexing & Retrieval Engine
Make the collected corpus searchable by building an inverted index[2][20]:

* Text Preprocessing: Tokenize the text, remove common stop-words, and apply stemming/lemmatization (e.g., using Porter stemmer or spaCy)[2][21].
* Search Engine Backend: Deploy an inverted index using Elasticsearch, OpenSearch, or an information retrieval library like PyTerrier[19][20].
* Multi-Field Indexing: Map title, kicker/category, author, published_date, and body as distinct fields[20].
* Scoring Function: Configure Okapi BM25 as the primary term-matching and ranking model, giving higher weight to title and kicker matches over body occurrences[3][22].

Phase 6: Search Interface & Query Evaluation
Deliver the search engine to users and evaluate relevance:

* User Query Interface: Build a web UI or REST API (e.g., with FastAPI/Flask) that accepts keyword queries, date range filters, and publication category filters[23][24].
* Result Presentation: Display ranked search snippets containing the article title, publication date, source outlet, and highlighted matching context[25][26].
* Advanced Contextual Features (TREC Models):
    * Named Entity Recognition (NER): Extract entities (PERSON, ORG, GPE, EVENT) from top retrieved documents[21].
    * Background Linking: Automatically suggest 2-3 related background stories for a chosen article to provide context for unfolding events[27][28].
